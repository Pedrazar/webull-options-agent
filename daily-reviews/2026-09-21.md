## Bug found and fixed: phantom trade-log entry for an unfilled order

The 9:45am `put_sold` entry claimed $625 was collected. Checking the actual order via `getOrderDetail()` showed it ended `status: CANCELLED, filled_quantity: 0` — it never became a real position. Confirmed directly against live positions: only ONE option position exists (5 contracts, matching the 10:00am order's $1.04 fill), not ten — so **the strategy never double-sold**, the broker-truth `reconcile()` design caught and self-corrected this automatically on the very next tick, exactly as designed.

The actual bug was narrower but real: `sellToOpen()` (and the call-sell and buy-to-close paths) polled for order-fill confirmation but never gated on the result — a cancelled/rejected/unconfirmed order still got logged as a success, falling back to the requested price. Fixed: all three paths now only log a sale/close when the fill is confirmed `FILLED`; anything else logs an honest `guard_rejected(reason: "order_not_filled")` instead. Per the project's append-only log convention, the phantom 9:45am entry was not deleted — it's flagged here and in `CLAUDE.md` instead.
